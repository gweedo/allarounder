# Fix stale context before running E3

> E2 research output (2026-10-18, `NEXT-STEPS-PROMPT.md`). Produced with the deep-research skill; the source notes are in [`notes/`](notes/). The recommendations below are a snapshot: the P0/P1 items are applied in a follow-up PR.

The biggest context risk in this repo is stale context, not too much context. The always-loaded floor is modest: about **10k tokens** across CLAUDE.md, MEMORY.md and skill listings ([repo_audit](notes/repo_audit.md)). The trouble is that the files a fresh session trusts most now contradict the repo. CLAUDE.md claims Windows/PowerShell and an "in progress" pipeline. NEXT-STEPS-PROMPT.md says no credentials exist. CONTEXT.md describes view-time rendering, which is the exact topic of E3. Four memory entries point at the retired Azure stack, and one memory is plainly false. The Matt Pocock baseline still holds and is consistent with Anthropic's guidance. That baseline is: one unbroken window from grill to issues, `/handoff` when you branch off or run low, and a fresh session per `/implement` issue. Anthropic says performance "degrades as [context] fills" and that "a clean session with a better prompt almost always outperforms a long session" ([Best practices](https://code.claude.com/docs/en/best-practices)). One fact changes how you run it. This session's model, Opus 5.5, has a 1M window and auto-compacts at **about 967K** ([Model configuration](https://code.claude.com/docs/en/model-config)). The ~120k "smart zone" is therefore about 12% of the window, so the harness will never enforce it for you. Recommended order: first clean up the context E3 will read, in its own PR, then run E3 with a manual token alarm and no compaction.

## The 120k smart zone is a heuristic you must enforce yourself

The ~120k figure is Pocock's personal threshold ("around the 120k token mark, I start to feel like I'm in the dumb zone"), not a measurement ([SozAI transcript](https://sozai.app/transcript/handoff-new-favourite-skill/index.md)). Other practitioners put the line anywhere from 100k to 150k ([aihero](https://www.aihero.dev/ai-coding-dictionary/smart-zone)). The direction of the effect is well supported. Chroma found degradation with input length in **every experiment across 18 models**, and the effect was worst with near-miss distractors and coherent text ([Chroma](https://www.trychroma.com/research/context-rot)), which describes a typical coding session. Anthropic calls it "a performance gradient rather than a hard cliff" ([Anthropic Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Anthropic's own 1M-context recall scores (78.3% MRCR v2 at 1M) measure retrieval, not judgment over a polluted history ([1M GA](https://claude.com/blog/1m-context-ga)). Keep 120k as a habit for when to wrap up.

Compaction is lossy on exactly what a brainstorm builds up. It drops full tool outputs, intermediate reasoning and early detailed instructions. Root CLAUDE.md, MEMORY.md, up to 5 recent files and invoked skill bodies (capped at 5k tokens each) come back from disk ([Context window](https://code.claude.com/docs/en/context-window)). Anthropic's long-running-agent harness concluded that "compaction isn't sufficient" and carries state in progress files plus git instead ([Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). The rule for this repo is: use `/handoff` (a file plus a fresh session) to cross a phase or task boundary, use `/compact <focus>` only at an intentional break inside one task, and use `/clear` freely between unrelated tasks, since `/clear` "costs nothing" while compaction is itself a large request ([Manage costs](https://code.claude.com/docs/en/costs)).

## Subagents keep exploration out of the window, with two caveats

Delegate read-heavy, self-contained work: broad code sweeps, web research, log and test triage, fresh-eyes diff review. A subagent may spend tens of thousands of tokens and return a summary of about **1–2k** ([Anthropic Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Keep iterative, tightly coupled work in the main thread ([Subagents](https://code.claude.com/docs/en/sub-agents)). There are two caveats. First, **Explore and Plan skip CLAUDE.md**, so they don't know the Italian/English rule or the settled architecture. That is fine for search but wrong for drafting anything. Second, a **fork** inherits the conversation and shares the prompt cache, so use it when the side task needs what the main thread knows. Use a fresh subagent when you want no bias, as in review ([Subagents](https://code.claude.com/docs/en/sub-agents)).

For a handoff file, the strongest evidence favors short files that reference durable artifacts. Use this shape: goal of the next session, current state verified by command output (branch, last commit, tests), decisions with links to the ADR or issue, dead ends not to retry, open questions, ordered next steps, and suggested skills. This combines the local `/handoff` skill's "reference, don't duplicate" rule with Anthropic's progress-file harness ([Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). Because handoffs point at docs instead of copying them, a stale CONTEXT.md or NEXT-STEPS gets carried into every hop. That is a second reason the P0 fixes come first.

## How to run E3

| Step | Session | Context rule |
|---|---|---|
| 0. Prep | Separate session and PR: P0-1 to P0-3, plus P1-1 if possible. Merge, then **restart**. | CLAUDE.md edits apply only in a new session |
| 1. `/grill-with-docs` | **Window A**, fresh. Ask a subagent to map the conversion chain (Doc export → `src/pipeline/ingest` → Markdown → `lib/markdown.ts` → HTML) and return a summary with file:line pointers, so the code reading never enters Window A. Record terms in CONTEXT.md as you go, and decisions as a new ADR superseding the current approach. | No `/compact`, no `/clear` |
| 2. `/prototype` (optional) | `/handoff` out of Window A, open **Window B** against the file, prototype (e.g. export a real Doc and diff each stage), `/handoff` back, then **read that file into Window A**. | Window A stays unbroken. Only the summary returns |
| 3. `/to-prd` → `/to-issues` | Window A. | Still no compaction. If the status line passes ~120k before `/to-issues`, `/handoff` and continue in a fresh thread rather than pushing on |
| 4. `/implement` × N | `/clear`, then **one fresh session per issue**, given the PRD and that single issue. The issue is the handoff, so no handoff file is needed. Close with a fresh-context `/review`. | One issue per window |

Three cautions. First, `/handoff` writes to the OS temp dir, and in this devcontainer `/tmp` may not survive a container rebuild between Window A and Window B. Check that, or point E3 handoffs at a gitignored workspace path (e.g. `.claude/handoffs/`). Second, do **not** lower `/autocompact` to approximate the smart zone (the minimum is 100K): an auto-compact firing mid-grill is exactly the mid-phase compaction the flow forbids. Use the token alarm and a manual `/handoff`. A high `/autocompact` set well above the handoff point is optional insurance, and that is my judgment, since the docs give no recommended value. Third, during `/implement` the ponytail trial's "one small test" stance can pull against ADR-0009 TDD, and CLAUDE.md wins ([project-ponytail-trial] (`~/.claude/projects/-workspaces-Podcast-Blog-Build/memory/project-ponytail-trial.md`)).

## Conclusion

The repo's context problem is correctness, not volume: a session can only be as good as the files it trusts at startup, and four of those files have drifted since the pivot. The deeper fix is to give each kind of state one owner. CLAUDE.md holds durable rules. GitHub issues and PRDs hold task state. ADRs and DECISIONS.md hold decisions. Auto-memory holds only what lives outside the repo. NEXT-STEPS-PROMPT.md is either kept to a short queue or retired in favor of issues. Two things remain uncertain. No benchmark validates 120k for 2026 models, so it could reasonably move higher once you see how E3's window behaves. No published data compares compaction quality against handoff quality.
