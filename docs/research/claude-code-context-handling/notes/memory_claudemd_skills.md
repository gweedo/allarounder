# Claude Code persistent-context mechanisms: CLAUDE.md, auto memory, rules, skills (as of Oct 2026)

Source legend: **[OFFICIAL]** = code.claude.com docs (fetched 2026-10-18, current; many statements reference CLI versions up to v2.1.28x) or Anthropic/claude.com blog. **[PRACTITIONER]** = opinion/third-party. **[RESEARCH]** = academic paper. Version-gated behaviour is noted where the docs state it.

## 1. CLAUDE.md: size, content, hierarchy, imports, rules, compaction

### Takeaway
Official guidance is now explicit: **under 200 lines per CLAUDE.md file**, only facts needed in *every* session (build/test commands, conventions that differ from defaults, repo etiquette, non-obvious gotchas, project-specific architectural decisions); move multi-step procedures to skills and area-specific guidance to path-scoped `.claude/rules/`. `@imports` organize but do **not** save context. After `/compact`, project-root CLAUDE.md and unscoped rules are re-read from disk; nested CLAUDE.md and path-scoped rules are not (they reload only when a matching file is touched again).

### Cited Findings

**What to put in / keep out**
- [OFFICIAL] "Keep it to facts Claude should hold in every session: build commands, conventions, project layout, 'always do X' rules. If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule instead." Triggers to add something: Claude makes the same mistake twice; a code review catches something Claude should have known; you retype the same correction; a new teammate would need it. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Include/Exclude table: **Include** bash commands Claude can't guess; code style rules that differ from defaults; testing instructions/preferred runners; repo etiquette (branch naming, PR conventions); architectural decisions specific to the project; dev environment quirks (required env vars); common non-obvious gotchas. **Exclude** anything Claude can figure out by reading code; standard language conventions; detailed API docs ("link to docs instead"); information that changes frequently; long explanations/tutorials; file-by-file descriptions of the codebase; self-evident practices like "write clean code". — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Pruning test: "For each line, ask: 'Would removing this cause Claude to make mistakes?' If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" Symptom of bloat: "If Claude keeps doing something you don't want despite having a rule against it, the file is probably too long and the rule is getting lost." Anti-pattern "The over-specified CLAUDE.md ... Claude ignores half of it because important rules get lost in the noise. Fix: Ruthlessly prune. If Claude already does something correctly without the instruction, delete it or convert it to a hook." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Emphasis: "If Claude keeps skipping one instruction, add emphasis such as 'IMPORTANT' to that line alone. If you emphasize many lines, none of them stands out." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Instructions should be concrete/verifiable ("Use 2-space indentation" not "Format code properly"); grouped under headers/bullets; contradictory instructions may be resolved arbitrarily. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] `/doctor` "proposes trims for a checked-in CLAUDE.md: it cuts content Claude can derive from the codebase, such as directory layouts, dependency lists, and architecture overviews, and keeps pitfalls, rationale, and conventions that differ from tool defaults." `/doctor prompt-audit` (v2.1.283+) reports outdated/conflicting instructions, references to non-existent files/commands, and instructions written for older models, across CLAUDE.md, rules, skills, commands, subagents, output styles; proposes edits, changes nothing until asked. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] CLAUDE.md is advisory, not enforced: "CLAUDE.md content is delivered as a user message after the system prompt, not as part of the system prompt itself ... there's no guarantee of strict compliance." Things that must happen every time (before each commit, after each edit) belong in hooks; hard blocks in permissions/`PreToolUse` hooks. — [Memory docs](https://code.claude.com/docs/en/memory); "Put guardrails in hooks. An instruction like 'never edit .env' in CLAUDE.md or a skill is a request, not a guarantee." — [Features overview](https://code.claude.com/docs/en/features-overview)
- [OFFICIAL] If CLAUDE.md sets commit/PR rules, they may compete with built-in git guidance; turn that off with `includeGitInstructions` and set `attribution`. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Block-level HTML comments (`<!-- ... -->`) are stripped before injection, so maintainer notes cost no tokens (comments inside code blocks are kept). — [Memory docs](https://code.claude.com/docs/en/memory)

**Size limits and warnings**
- [OFFICIAL] "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Repeated in the features overview ("Rule of thumb: Keep CLAUDE.md under 200 lines") and the claude.com blog ("Keep CLAUDE.md under 200 lines, give it an owner, and review changes to it like code"). — [Memory docs](https://code.claude.com/docs/en/memory); [Features overview](https://code.claude.com/docs/en/features-overview); [Steering Claude Code blog, 2026-06-18](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)
- [OFFICIAL] Hard limit: a CLAUDE.md up to **4 MiB** loads in full; a larger file is skipped. Startup and `/status` warn when a file exceeds the recommended length, and also when files that are each within length "add up past a combined limit at session start"; each CLAUDE.md, rules file and `@import` counts as a separate file. (The combined-limit figure is not stated.) — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Representative token cost in Anthropic's context-window simulation: system prompt ~4,200 tokens, project CLAUDE.md ~1,800, `~/.claude/CLAUDE.md` ~320, MEMORY.md ~680, skill descriptions ~450, deferred MCP tool names ~120 (illustrative numbers, not limits). — [Context window](https://code.claude.com/docs/en/context-window)
- [PRACTITIONER] HumanLayer (Kyle, 2025-11-25): their root CLAUDE.md is under 60 lines; "community consensus" ceiling ~300 lines, shorter preferred; says Anthropic gave no official figure (now outdated, since the docs say 200 lines). — [HumanLayer: Writing a good CLAUDE.md](https://www.humanlayer.dev/blog/writing-a-good-claude-md)
- [PRACTITIONER] Third-party skills.sh "Progressive Disclosure CLAUDE.md" skill suggests 40–50 lines max for the root file; not traced to an authoritative source. — [skills.sh](https://www.skills.sh/ravnhq/ai-toolkit/agent-init-deep) (via search; unverified)

**Hierarchy and load order**
- [OFFICIAL] Scopes, loaded broadest to most specific (later = read last): Managed policy (`/etc/claude-code/CLAUDE.md` on Linux/WSL, `/Library/Application Support/ClaudeCode/CLAUDE.md` macOS, `C:\Program Files\ClaudeCode\CLAUDE.md` Windows; or a `claudeMd` key in managed settings; can't be excluded) → User `~/.claude/CLAUDE.md` → Project `./CLAUDE.md` or `./.claude/CLAUDE.md` → Local `./CLAUDE.local.md` (gitignore it). — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Files from cwd **and every ancestor directory** load at launch, concatenated (not overriding), root-down; `CLAUDE.local.md` appended after `CLAUDE.md` at each level. **Subdirectory** CLAUDE.md files load lazily, when Claude reads/writes/edits a file in that subdirectory (a single-file `cat`/`head` counts as a read); they don't show under "Memory files" in `/context`. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] `claudeMdExcludes` (glob on absolute paths, any settings layer, arrays merge) skips unwanted ancestor CLAUDE.md/rules in monorepos. `--add-dir` directories don't load CLAUDE.md unless `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] AGENTS.md (v2.1.277+): read by default only when no CLAUDE.md/CLAUDE.local.md exists in cwd or above; configurable via `/config` → Project instructions (`claude-md-or-agents-md` default, `claude-md-and-agents-md`, `claude-md`, `managed-only`). A CLAUDE.md that says *in words* "read AGENTS.md" only works if Claude chooses to open it; use `@AGENTS.md` import instead. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Subagents get CLAUDE.md and git status at startup, except the built-in Explore and Plan agents (neither) and agents with `omitClaudeMd`. — [Features overview](https://code.claude.com/docs/en/features-overview)

**@imports**
- [OFFICIAL] `@path/to/file` syntax, relative to the importing file, recursive to max depth **four hops**; spaces need backslash-escaping (`@Design\ Docs/x.md`), quoted paths aren't imported; text in backticks/code blocks is not imported. External imports (outside cwd) trigger a one-time approval dialog per project. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] **Imports don't reduce context cost**: "Imports help you organize a long file but don't reduce its context cost, because imported files also load at launch." — [Memory docs](https://code.claude.com/docs/en/memory)

**.claude/rules/**
- [OFFICIAL] `.claude/rules/**/*.md` (recursive, symlinks supported). Without `paths` frontmatter: load at launch with same priority as `.claude/CLAUDE.md`. With `paths:` (globs, YAML list or comma string, brace expansion within a 1,000-pattern/4 MiB budget): load only when Claude Reads/Writes/Edits a matching file (or single-file `cat`/`head`). `paths` is the only frontmatter field read; bad YAML → treated as unscoped. User-level `~/.claude/rules/` load before project rules; conflicts are not resolved by precedence ("Claude may follow either one"). — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] "Rules load into context every session or when matching files are opened. For task-specific instructions that don't need to be in context all the time, use skills instead." — [Memory docs](https://code.claude.com/docs/en/memory)

**Compaction**
- [OFFICIAL] "What survives compaction" table: system prompt & output style still apply; **project-root CLAUDE.md and unscoped rules: re-injected from disk**; **auto memory: re-injected from disk**; git status refreshed; plan-mode plan re-injected; **rules with `paths:` and nested CLAUDE.md: reload on demand only**; up to 5 most-recently-modified read/edited files re-read (files >5,000 tokens come back as path references); invoked skill bodies re-injected capped at 5,000 tokens/skill and 25,000 total, oldest dropped; hook-added context summarized; `SessionStart` hooks matching `compact` re-run. "If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md." — [Context window](https://code.claude.com/docs/en/context-window)
- [OFFICIAL] Instructions given only in chat are lost on compaction; put them in CLAUDE.md. CLAUDE.md can steer compaction ("When compacting, always preserve the full list of modified files and any test commands"). — [Memory docs](https://code.claude.com/docs/en/memory); [Best practices](https://code.claude.com/docs/en/best-practices)

**Evidence that bloat hurts instruction-following**
- [RESEARCH] IFScale ("How Many Instructions Can LLMs Follow at Once?", Jaroslawicz et al., arXiv 2507.11538, July 2025): 20 models, up to 500 simultaneous keyword-inclusion instructions; best frontier models reach only ~68% accuracy at 500; three distinct degradation patterns correlated with model size/reasoning; primacy bias toward earlier instructions. (Pre-dates current models; task is synthetic keyword inclusion, not coding.) — [arXiv](https://arxiv.org/abs/2507.11538)
- [PRACTITIONER] HumanLayer's reading of that research: frontier thinking models follow ~150–200 instructions reasonably; Claude Code's own system prompt already has ~50 instructions; quality drops uniformly across all instructions as count rises (not just the later ones); models favour start and end of prompt. — [HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)
- [OFFICIAL] Anthropic context-engineering post (2025-09-29): "context rot" — recall decreases as context fills; LLMs have a finite "attention budget" where "every new token introduced depletes this budget"; aim for "the smallest set of high-signal tokens that maximize the likelihood of your desired outcome." Describes Claude Code as hybrid: "CLAUDE.md files are naively dropped into context up front," while glob/grep retrieve just-in-time. — [Anthropic Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] "LLM performance degrades as context fills ... Claude may start 'forgetting' earlier instructions." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [PRACTITIONER] HumanLayer claims Claude Code wraps CLAUDE.md in a reminder saying "IMPORTANT: this context may or may not be relevant to your tasks. You should not respond to this context unless it is highly relevant to your task," so Claude may skip instructions it deems irrelevant — an argument for keeping only universally applicable content. — [HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md). Not confirmed in official docs (which say only "delivered as a user message after the system prompt"); wrapper wording may differ by version/context.
- [PRACTITIONER] HumanLayer: don't use CLAUDE.md as a linter — use deterministic formatters/linters (e.g. via a Stop hook); avoid blind `/init` output because CLAUDE.md is the harness's highest-leverage point; structure as WHAT (stack, map) / WHY (purpose) / HOW (how to work and verify). — [HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md). Note official docs *do* recommend `/init` as a starting point, then refine.

### Inferences
- The 200-line target is per file, but the combined-limit warning and the shared attention budget mean the real budget is *all always-loaded text* (user + project + local CLAUDE.md + unscoped rules + imports + MEMORY.md + skill listing). Splitting via `@import` or unscoped rules doesn't help; only path-scoping, skills, or by-reference docs reduce the cost.
- Path-scoped rules have a hidden cost after compaction: they disappear until a matching file is touched again. Critical cross-cutting rules belong in root CLAUDE.md.
- Lines describing architecture/directory layout are exactly what `/doctor` cuts; rationale and non-default conventions are what it keeps.

### Gaps
- The numeric "combined limit" for the multi-file startup warning isn't published.
- No official A/B data on adherence vs CLAUDE.md length; the 200-line figure is guidance, and research evidence (IFScale) is synthetic and from mid-2025 models.
- Exact current wrapper text around CLAUDE.md injection is not documented officially.

## 2. Auto memory: mechanics, truncation, hygiene

### Takeaway
Auto memory is on by default: Claude writes one-fact-per-file notes under `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index; only the **first 200 lines or 25KB (whichever first)** of `MEMORY.md` load at session start, and topic files load on demand. Since v2.1.210 Claude Code warns near the limit and errors when a write leaves the index over it. It is re-injected after compaction, but not loaded into (non-fork) subagents.

### Cited Findings
- [OFFICIAL] Four memory types, recorded as frontmatter `type`: `user` (role, expertise, preferences), `feedback` (corrections and confirmed approaches), `project` (ongoing work, deadlines, decisions not derivable from code/git), `reference` (where to find external info, e.g. issue tracker). "Claude skips anything it can derive from the codebase, such as architecture, file paths, or debugging fixes. It also skips anything your CLAUDE.md files already say." — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Location `~/.claude/projects/<project>/memory/`, derived from the git repo so all worktrees/subdirectories share one directory; machine-local, not synced; override via `autoMemoryDirectory`; disable via `/memory` toggle (`autoMemoryEnabled`), per-project setting, or `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Memory files are excluded from the `cleanupPeriodDays` transcript sweep — they persist until edited/deleted. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] "The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, are loaded at the start of every conversation. Content beyond that threshold is not loaded." Topic files are not loaded at startup; Claude reads them with normal file tools when needed. The limit applies only to MEMORY.md. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Near-limit: Claude Code reminds Claude to "keep one line per entry, move detail into topic files, and merge or drop stale entries." Over-limit: the write succeeds but returns an error, e.g. "this write left the memory index at MEMORY.md at 214 lines, over its 200-line read limit ... Rewrite it to under 140 lines now". Before v2.1.210 an over-limit index was silently truncated. Since v2.1.211, YAML frontmatter and block HTML comments are excluded from the measurement. — [Errors reference](https://code.claude.com/docs/en/errors)
- [OFFICIAL] Since v2.1.214, writes to memory files with frontmatter get an auto-maintained `modified` ISO-8601 timestamp, so staleness is visible to both user and Claude. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Main-session auto memory is not loaded into subagents (forks excepted); subagents can have their own via the `memory` field. — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] "Remember X" requests go to auto memory; to put something in CLAUDE.md, ask explicitly ("add this to CLAUDE.md"). Audit with `/memory` (open folder; all files are plain markdown). — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Auto memory vs CLAUDE.md: CLAUDE.md = you write, instructions/rules, project/user/org scope; auto memory = Claude writes, learnings/patterns, per-repo. Use auto memory for "your preferences, corrections you give Claude, project context Claude can't derive from the code." — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Representative MEMORY.md cost in the simulation: ~680 tokens. — [Context window](https://code.claude.com/docs/en/context-window)

### Inferences
- Hygiene practices follow from the docs: one line per index entry; delete or rewrite `project`-type memories when the work ships or a decision is superseded (they describe transient state and go stale fastest); don't duplicate what CLAUDE.md or repo docs say (Claude is told to skip those, but older memories may predate that); use the `modified` timestamp to find stale entries.
- Because only the index is always loaded, a long index line costs every session while the topic file costs nothing until read. Keep index lines short hooks; keep detail in topic files.
- Memories are machine-local and invisible to teammates/CI; anything a collaborator or another machine needs belongs in the repo (CLAUDE.md or docs), not auto memory.
- Observed in this repo (2026-10-18): CLAUDE.md is 96 lines / ~9 KB; MEMORY.md index is 18 lines, with 16 topic files; several entries are marked RETIRED/history-only, which are candidates for pruning.

### Gaps
- No official guidance on how often to prune or a recommended number of memories; no published evidence on the effect of stale memories on behaviour.
- Docs don't say whether Claude proactively deletes memories it finds outdated.

## 3. Skills: progressive disclosure and the cost of many skills

### Takeaway
Only each skill's name + description (description + `when_to_use`, capped at 1,536 chars) is always in context; the SKILL.md body loads on invocation, and supporting files only when read. The whole listing has a budget of **1% of the model's context window**; over budget, descriptions for the least-used skills are dropped (names kept), which hurts auto-triggering. `disable-model-invocation: true` or `skillOverrides` remove a skill from the listing entirely. Move content from CLAUDE.md to a skill when it's a procedure or reference that's needed only sometimes.

### Cited Findings
- [OFFICIAL] Three levels: (1) `name`+`description` metadata preloaded into the system prompt at startup; (2) SKILL.md body loaded when Claude judges it relevant; (3) linked files (e.g. `reference.md`, `forms.md`) read only as needed; scripts can run without their contents entering context. "The amount of context that can be bundled into a skill is effectively unbounded." Agent Skills became an open standard 2025-12-18. — [Anthropic Engineering: Agent Skills (2025-10-16)](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- [OFFICIAL] "Unlike CLAUDE.md, a skill's body loads only when it's used, so long reference material costs almost nothing until you need it." Keep SKILL.md under **500 lines**; move detail to separate files referenced from SKILL.md. Once loaded, "every line is a recurring token cost". — [Skills docs](https://code.claude.com/docs/en/skills)
- [OFFICIAL] Description cap: combined `description` + `when_to_use` "is truncated at 1,536 characters in the skill listing"; configurable via `skillListingMaxDescChars`. Put the key use case first. — [Skills docs](https://code.claude.com/docs/en/skills)
- [OFFICIAL] Listing budget: "The listing always contains every skill name, but if you have many skills, Claude Code drops some descriptions to fit the listing's character budget, which removes the keywords Claude needs to match your request. The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least." Raise via `skillListingBudgetFraction` (e.g. `0.02`) or `SLASH_COMMAND_TOOL_CHAR_BUDGET`. `/context` Skills row shows post-budget size (since v2.1.196); `/doctor` estimates listing cost; overflow warns in `--debug` log. — [Skills docs](https://code.claude.com/docs/en/skills)
- [OFFICIAL] "Every skill in the skill listing adds to your context on every turn, whether or not Claude ever uses it." `/skill-doctor` (v2.1.252+) reports per-skill context cost and usage, flags never-invoked skills, lists unused plugins. — [Skills docs](https://code.claude.com/docs/en/skills)
- [OFFICIAL] Visibility controls: `disable-model-invocation: true` → description not in context, user-only (`/name`), zero cost until invoked (recommended for side-effecting skills); `user-invocable: false` → model-only, hidden from `/` menu. `skillOverrides` in settings (for skills you don't want to edit): `on` / `name-only` (listed without description) / `user-invocable-only` / `off`; doesn't apply to plugin skills (use `/plugin`). — [Skills docs](https://code.claude.com/docs/en/skills); [Features overview](https://code.claude.com/docs/en/features-overview)
- [OFFICIAL] Vague or overlapping descriptions cause wrong or missed skill loads; invoke `/name` explicitly to force one. — [Features overview](https://code.claude.com/docs/en/features-overview)
- [OFFICIAL] Lifecycle: rendered skill content enters the conversation once and stays; it isn't re-read. After compaction, the most recent invocation of each skill is re-attached, first 5,000 tokens each, 25,000 total, most-recent first — "put the most important instructions near the top of SKILL.md". The skill *listing* itself is **not** re-injected after `/compact`; only invoked skills are preserved. — [Skills docs](https://code.claude.com/docs/en/skills); [Context window](https://code.claude.com/docs/en/context-window)
- [OFFICIAL] In subagents, skills in the `skills:` field are fully preloaded at launch (not progressive). `context: fork` runs a skill in an isolated subagent that doesn't see conversation history. — [Skills docs](https://code.claude.com/docs/en/skills)
- [OFFICIAL] When to move content from CLAUDE.md into a skill: "Put it in a skill if it's reference material Claude needs sometimes (API docs, style guides) or a workflow you trigger with /<name> (deploy, review, release)"; trigger "You paste the same playbook or multi-step procedure into chat for the third time → Capture it as a skill". Combined pattern: "CLAUDE.md says 'follow our API conventions,' a skill contains the full API style guide." — [Features overview](https://code.claude.com/docs/en/features-overview); "Instructions that are procedural, like deploy workflows, release checklists, or review processes, belong in a skill rather than in CLAUDE.md." — [Steering Claude Code blog](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)
- [PRACTITIONER] Matt Pocock (AI Hero): progressive disclosure = give the agent only what it needs now, with pointers to the rest; a skill is "the unit of progressive disclosure in a harness"; on putting a style guide in AGENTS.md: "No — progressive disclosure. Reference the style guide as a skill the agent loads when it actually needs to write a component. AGENTS.md pays the token cost every turn." — [AI Hero dictionary](https://www.aihero.dev/dictionary/progressive-disclosure), [AI Hero: skill](https://www.aihero.dev/ai-coding-dictionary/skill) (quotes from search snippets; direct fetch returned 404, so unverified verbatim)

### Inferences
- With dozens of plugin skills installed (as in this environment), the 1% listing budget is likely to overflow, so descriptions of rarely used skills get dropped and auto-triggering of those skills becomes unreliable. Pruning unused plugins or setting `name-only`/`off` keeps the important descriptions intact.
- Side-effecting or rarely needed skills should be `disable-model-invocation: true`: they cost nothing until typed.

### Gaps
- Docs don't state whether the 1% budget is measured in tokens or characters per token of window (it says a "character budget" that "scales at 1%"); exact default character count for a 200k vs 1M window isn't given.
- No official data on how skill-trigger accuracy degrades with listing size.

## 4. Docs pulled in by reference vs inlined

### Takeaway
Three tiers exist: **inlined/imported** (`@path`: always loaded, full cost every session), **by-reference pointer** ("read docs/X before Y": costs one line until Claude chooses to read it, but compliance depends on Claude deciding to open it), and **skills/path-scoped rules** (harness-triggered loading). Official docs and practitioners favour pointers/skills for detailed or occasional material and inlining only what every task needs.

### Cited Findings
- [OFFICIAL] Exclude "Detailed API documentation (link to docs instead)" from CLAUDE.md. — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] `@import` expands at launch and doesn't reduce context cost; a sentence telling Claude in words to read a file means "Claude sees [it] only if it decides to open the file". — [Memory docs](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Just-in-time retrieval: agents "maintain lightweight identifiers (file paths, stored queries, web links, etc.)" and load data at runtime; Claude Code combines up-front CLAUDE.md with just-in-time file navigation. — [Anthropic Engineering: context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [PRACTITIONER] HumanLayer: put task-specific docs in e.g. `agent_docs/building.md`, `agent_docs/testing.md`, list them in CLAUDE.md with a short description of each, and prefer `file:line` pointers over copied code snippets (which go stale). — [HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)
- [PRACTITIONER] CodeMySpec recommends a short root CLAUDE.md acting as a table of contents pointing to docs. — [CodeMySpec](https://codemyspec.com/blog/progressive-disclosure) (via search snippet; not fetched)

### Inferences
- A by-reference pointer with an explicit trigger ("Before proposing architecture, read docs/DECISIONS.md") is the cheapest option for large, occasionally needed docs, but it's the least reliable: it's a request Claude may skip. For must-follow material tied to specific files, path-scoped rules make loading automatic; for procedures, a skill gives both on-demand loading and a `/name` trigger.
- Pointers stay valid after compaction (the root CLAUDE.md is re-injected), whereas the content Claude read through them is summarized away, so re-reading may be needed.
